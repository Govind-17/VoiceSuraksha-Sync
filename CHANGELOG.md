# Security & Architecture Changelog

Status summary of all 22 roadmap items across Phases 1–5:

1. **Server-side spoken challenge enforcement (`app/asr.py`, `app/main.py`)** — **DONE**: Client transcripts ignored in `LIVE` mode; real `ServerASRAdapter` supports Sarvam, Deepgram, and Groq and fails closed to `REVIEW / HOLD` (`ASR_UNAVAILABLE`) on outage.
2. **Server-derived policy context (`app/main.py`, `app/models.py`)** — **DONE**: IST `after_hours`, DB-backed `privileged_role`, and admin-only banking `amount_inr` enforced server-side.
3. **Fail-closed LIVE secrets & DB durability (`app/auth.py`, `app/db.py`)** — **DONE**: Startup blocks default/`<16`-char secrets in `LIVE` mode; `schema_version` migrations and PostgreSQL `DATABASE_URL` supported cleanly.
4. **Normalize transcript noise safely (`app/policy.py`)** — **DONE**: Bounded digit-word and homophone normalization preserving exact token match for challenge code words and digits.
5. **Unified fail-closed outcomes (`app/policy.py`, `app/main.py`, `frontend/index.html`)** — **DONE**: Consistent 4-outcome vocabulary (`APPROVED`, `STEP-UP`, `REVIEW / HOLD`, `REJECTED`), with fallbacks on `HOLD`/`STEP-UP` and immediate `REJECTED` on fake/no-match even if ASR is down.
6. **Step-up completion & admin reviewer queue (`app/main.py`, `frontend/index.html`)** — **DONE**: Added `/step-up/complete` (`trusted_app_push`, `manager_callback`, `in_store_kyc`), banking high-value threshold re-evaluation, single-token enforcement (`409` on replay), and `/admin/review-queue` + `/review` audit logging.
7. **Cross-domain alert escalation, TTL & resolve (`app/main.py`, `app/policy.py`)** — **DONE**: Unexpired `SIM_SWAP_ATTEMPT_BLOCKED` triggers `STEP-UP` (`CROSS_DOMAIN_ALERT`) with admin `/risk-events/{id}/resolve`; `emergency_sim_block` stays low-friction.
8. **Perceptual audio replay detection (`app/audio_fingerprint.py`, `app/main.py`)** — **DONE**: 64-bit NumPy spectral delta fingerprint (`<= 8` Hamming bits) blocks volume-scaled/trimmed replays alongside exact SHA-256.
9. **Concurrent multi-segment verification (`app/audio_fingerprint.py`, `app/main.py`)** — **DONE**: WAV `>= 8s` split into 2–3 overlapping slices evaluated concurrently; any `fake` rejects (`DEEPFAKE_SIGNAL`) and segment disagreement triggers second challenge.
10. **Borderline second-challenge lineage (`app/policy.py`, `app/main.py`)** — **DONE**: Borderline similarity or segment disagreement issues linked `followup_session` (`challenge_attempt=2`) and escalates repeated borderline to `REVIEW / HOLD`.
11. **Hybrid rate limiting & login lockout (`app/rate_limit.py`, `app/main.py`)** — **DONE**: Per-IP/username 5-fail lockout and sliding-window limits backed by memory + SQLite return HTTP `429` + `Retry-After` + `RATE_LIMITED` audit events.
12. **Explicit consent text, re-enrollment gate & cooldown (`app/models.py`, `app/main.py`)** — **DONE**: Mandatory `consent_text`, non-admin re-enrollment gated by `verified_session_id`, and 24h `NEW_ENROLLMENT_COOLDOWN` (`STEP-UP`) in `LIVE` mode.
13. **Tamper-evident audit SHA-256 hash chain (`app/policy.py`, `app/main.py`, `frontend/index.html`)** — **DONE**: `AuditEvent` links `prev_hash` → `entry_hash` verified via `/api/v1/audit/verify-chain`, exported in dossiers, and shown in the SOC header badge.
14. **Auth & HTTP header hardening (`app/auth.py`, `app/main.py`)** — **DONE**: PBKDF2-HMAC-SHA256 raised to `600_000` iterations with legacy 120k verification compatibility, UTF-8 byte `compare_digest`, `Secure` cookies in `LIVE` mode, and CSP/XSS/frame security headers.
15. **Atomic decision-token consume (`app/main.py`)** — **DONE**: Conditional SQL `UPDATE ... WHERE consumed_at IS NULL AND expires_at > now` enforces single-winner concurrency (`409` on race/replay).
16. **Contextual risk policy signals (`app/policy.py`, `app/main.py`, `frontend/index.html`)** — **DONE**: Simulated `sim_age_days` (`RECENT_SIM_SWAP`), `device_changed` (`DEVICE_CHANGED`), server-computed `call_velocity_1h` (`HIGH_CALL_VELOCITY` / `CALL_VELOCITY_HOLD`), and IST time-of-day rules documented in `GATEWAY_PROFILES`.
17. **Unlimited credits framing (`app/main.py`, `frontend/index.html`, `README.md`)** — **DONE**: Replaced `DetectifAI Credits` tile with `Decisions / min` and `p95 Latency`, reframing replay/quality gates as security and fast re-record UX.
18. **End-to-end clickable accessibility fallbacks (`app/main.py`, `frontend/index.html`)** — **DONE**: All 3 fallback buttons call `/step-up/complete` for `REVIEW / HOLD` and `STEP-UP` sessions with simulated audit entries and token release.
19. **Expanded 10-scenario Red-Team Attack Sandbox (`app/main.py`, `frontend/index.html`)** — **DONE**: Added `transcript_spoofing`, `reencoded_replay`, `policy_context_tampering`, `rate_limit_lockout`, and isolated `audit_chain_tamper` displaying Expected vs Actual.
20. **Accuracy evaluation script & dashboard card (`scripts/eval_accuracy.py`, `app/main.py`, `frontend/index.html`)** — **DONE**: Evaluates labeled WAV folders against DetectifAI API for real FAR/FRR and confusion matrix; dashboard shows `"No evaluation run yet"` until populated.
21. **Comprehensive automated test suite (`tests/test_gateway.py`)** — **DONE**: Expanded fixture/mock integration and negative security test suite past `45+` deterministic passing tests.
22. **Repository cleanup, README & Render config (`0.26.0`, `README.md`, `render.yaml`, `.gitignore`)** — **DONE**: Removed stray `0.26.0` artifact, ignored WAL/SHM/report files, updated `render.yaml`, and documented architecture, threat model, env vars, and honest limitations.
